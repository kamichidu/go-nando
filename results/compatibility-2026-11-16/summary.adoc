== E2E measurements

Each comparison run used 10 iterations and a 4,096-byte payload on an isolated local repository. All three interfaces completed 10/10 iterations in the first successful comparison set. Conditions and unmodified per-iteration records are in `benchmark-conditions.json` and `benchmark-*-first-success.json`. The earlier daemon startup failures are retained as `benchmark-*-initial-failure.json`; they are not included in the comparison.

These are end-to-end observations, not adapter-only costs. RPC creates a new Unix HTTP connection for each JSON-RPC call and includes begin/write/fsync/commit/release; FUSE traverses kernel requests with zero metadata TTLs and direct I/O, committing at fsync; WebDAV uses separate HTTP requests and measures PUT completion. Cache, connection reuse, and commit boundaries differ. Simple latency deltas do not isolate adapter thinness or overhead.

The following values are milliseconds. Percentiles use nearest-rank (`ceil(p*n)`, 1-indexed); at 10 samples p95 and p99 select the maximum observation. Successful iterations only are summarized. There are no CI performance thresholds.
