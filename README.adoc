= nando

`docs/design.ir.yaml` is the sole semantic authority and direct design reference for this repository. See `docs/design-ir-migration.md` for the one-time source coverage record.

== Validate the design

Check out the official Design IR validator and provide its path:

[source,bash]
----
git clone https://github.com/kamichidu/design-ir.git ../design-ir
git -C ../design-ir checkout 455ed318b7bc409d3e1da320620ef92d457042b9
DESIGN_IR_REPO=../design-ir tools/validate-design-ir.sh
----

The script verifies the pinned schema digest, then validates structure and semantics with the official v1alpha1 validator. Unresolved representation gaps are reported as warnings; validation errors fail the command.

== Reproducible E2E gates

Run host-native G0-G3 and WebDAV G5 checks with:

[source,bash]
----
e2e/run.sh
----

Docker Compose starts only fake GCS; the daemon, real FUSE mount, WebDAV adapter, scenario runner, and fault-injection proxy stay on the Linux/WSL host. The optional bounded binary/concurrency FUSE stress profile is `e2e/run.sh --stress`. Scenario assertions, host requirements, fake-GCS limitations, and retained evidence are documented in link:docs/e2e-gates.md[docs/e2e-gates.md].

== WebDAV Phase A

WebDAV is a separate Go module and process. Build it with `cd webdav && go build ./cmd/nando-webdav`. It connects to the daemon using public controlrpc and daemon-issued `file://` Resource URIs only. The Phase A server binds to loopback HTTP only; remote exposure is rejected until authentication and TLS policy are decided. Supported operations, ETag conditions, and deliberate protocol gaps are documented in link:docs/webdav-phase-a.adoc[WebDAV Phase A].

== Daemon maintenance scheduling

GCS delivery requires an explicit scheduler policy in the daemon's TOML config; timing and parallelism have no implicit operational defaults. Example values below are illustrative and must be selected for the deployment:

[source,toml]
----
gcs_sync_idle_interval = "30s"
gcs_sync_periodic_interval = "5m"
gcs_max_delivery_delay = "30m"
gcs_sync_parallelism = 2
----

The daemon runs transfer processing, Capacity GC, and Orphan/Invalid GC as independent tasks. GCS queue rows retain their durable enqueue timestamps so maximum-delay eligibility survives daemon restart. Idle is currently measured from the last successful content commit observed by the daemon; the Design IR still records the broader idle definition/default policy as an open decision. The scheduler also runs for Local repositories when these settings are explicitly configured; without an explicit policy, Local repositories keep their existing manual maintenance behavior.
