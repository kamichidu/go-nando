# S3-compatible storage

Amazon S3 and S3-compatible storage use the same S3 adapter. Amazon S3 is the AWS service; compatible services implement the S3 API and may differ in endpoint behavior. Authentication comes from the AWS SDK v2 Default Credential Chain. Do not put access keys or secret keys in TOML.

1. Configure an identity available through the AWS credential chain for the account that will run nando.
2. Save the runtime settings in a TOML file. For a non-AWS compatible service, such as Wasabi, set that service's endpoint and region. For Amazon S3, the endpoint can be omitted; set a region if needed. The selected endpoint must support the conditional single-part upload and checksum behavior required by nando.

   ```sh
   mkdir -p "$HOME/.config/nando"
   cat > "$HOME/.config/nando/s3.toml" <<'EOF'
   [remote.s3]
   endpoint = "https://s3.us-west-1.wasabisys.com"
   region = "us-west-1"

   [remote]
   sync_idle_interval = "30s"
   sync_periodic_interval = "5m"
   max_delivery_delay = "30m"
   sync_parallelism = 2
   EOF
   ```

   Replace the endpoint and region for your provider. The TOML file is read at runtime; backend and bucket selection are saved in the repository during initialization.

3. Initialize the repository with the same config and repository path that every later process will use.

   ```sh
   nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" init \
     --delivery-mode remote \
     --remote-backend s3 \
     --remote-uri s3://my-bucket/nando/
   ```

4. Keep the same config and repository selection for the daemon and one adapter. Start the daemon in one terminal and leave it running:

   ```sh
   nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" daemon
   ```

   In another terminal, start either FUSE or WebDAV:

   ```sh
   mkdir -p "$HOME/nando-mount"
   nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" fuse --fuse-mountpoint "$HOME/nando-mount"
   # Or: nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" webdav
   ```

The endpoint and region belong to runtime TOML; the backend and URI belong to the repository settings. Prefixes are concatenated literally to the object key. For example, `s3://bucket/nando` maps to `nandoobjects/{content_id}`, while `s3://bucket/nando/` maps to `nando/objects/{content_id}`. See [FUSE](../use/fuse) or [WebDAV](../use/webdav) for adapter behavior.
