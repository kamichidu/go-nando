# S3-compatible storage

Amazon S3 and S3-compatible services use the same `s3` backend. Select the backend and bucket URI when initializing the repository; configure the connection and delivery scheduler in the runtime TOML file used by the daemon. The endpoint and region belong under `[remote.s3]`. Access keys and secret keys must not be put in TOML.

Both procedures below use `--remote-backend s3`, an `s3://bucket[/prefix]` URI, the same daemon scheduler settings, and the AWS SDK for Go v2 default credential chain. Set up credentials for the operating-system account that runs the daemon. The chain can obtain credentials from environment variables, shared AWS configuration and credentials files, or supported workload credentials. For Amazon S3, use an IAM role or another AWS identity with access to the bucket. For a compatible service, provide that service's access key and secret through the environment or a credentials file supported by the chain.

## Amazon S3

For Amazon S3, normally omit `endpoint`; the SDK uses its Amazon S3 endpoint. Set the bucket's AWS region explicitly in `[remote.s3]`:

```sh
mkdir -p "$HOME/.config/nando"
cat > "$HOME/.config/nando/s3.toml" <<'EOF'
[remote.s3]
region = "us-west-2"

[remote]
sync_idle_interval = "30s"
sync_periodic_interval = "5m"
max_delivery_delay = "30m"
sync_parallelism = 2
EOF

nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" init \
  --delivery-mode remote \
  --remote-backend s3 \
  --remote-uri s3://my-bucket/nando/
nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" daemon
```

Replace `us-west-2` with the bucket's region and `my-bucket` with the bucket name. The AWS identity must be available to the daemon account through the SDK credential chain. For example, on AWS use an attached workload role; for local development, configure a profile in the account's AWS shared files or export the standard `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` variables before starting the daemon. Do not put these values in the TOML file.

## S3-compatible service example: Wasabi

Wasabi is one example of an S3-compatible service. Set both `endpoint` and `region` to values for the bucket's Wasabi region. The following example uses Wasabi US West 1 (Oregon):

```sh
mkdir -p "$HOME/.config/nando"
cat > "$HOME/.config/nando/s3.toml" <<'EOF'
[remote.s3]
endpoint = "https://s3.us-west-1.wasabisys.com"
region = "us-west-1"

[remote]
sync_idle_interval = "30s"
sync_periodic_interval = "5m"
max_delivery_delay = "30m"
sync_parallelism = 2
EOF

nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" init \
  --delivery-mode remote \
  --remote-backend s3 \
  --remote-uri s3://my-bucket/nando/
nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" daemon
```

Use the endpoint and region matching the bucket's actual Wasabi region; the example values are not universal. Supply the Wasabi access key and secret to the daemon account through `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, or through a profile in the AWS shared credentials/config files that the SDK can load. If using environment variables, export them in the daemon's environment before starting `nando daemon`. Keep them out of TOML and shell history.

## Start an adapter

Leave the daemon running. In another terminal, use the same config and repository path to start one adapter:

```sh
mkdir -p "$HOME/nando-mount"
nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" fuse --fuse-mountpoint "$HOME/nando-mount"
```

Or use WebDAV instead:

```sh
nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" webdav
```

The repository stores the selected backend and URI; the daemon reads the runtime endpoint, region, credentials, and scheduler settings. The URI prefix is concatenated literally to object keys, so a trailing `/` is not added automatically. For example, `s3://bucket/nando` maps to `nandoobjects/{content_id}`, while `s3://bucket/nando/` maps to `nando/objects/{content_id}`. The endpoint must support the conditional single-part upload and checksum behavior nando requires. See [Remote delivery](../use/remote-delivery) for delivery timing and durability behavior, and [FUSE](../use/fuse) or [WebDAV](../use/webdav) for adapter behavior.
