# S3-compatible storage

Amazon S3 and S3-compatible storage use the same S3 adapter. Amazon S3 is the AWS service; compatible services implement the S3 API and may differ in endpoint behavior. Authentication comes from the AWS SDK v2 Default Credential Chain. Do not put access keys or secret keys in TOML.

1. Configure an identity available through the AWS credential chain for the daemon account.
2. For a non-AWS compatible service, such as Wasabi, set that service's endpoint and region in the daemon TOML file. For Amazon S3, the endpoint can be omitted; set a region if needed. The selected endpoint must support the conditional single-part upload and checksum behavior required by nando.

   ```toml
   [remote.s3]
   endpoint = "https://s3.us-west-1.wasabisys.com"
   region = "us-west-1"

   [remote]
   sync_idle_interval = "30s"
   sync_periodic_interval = "5m"
   max_delivery_delay = "30m"
   sync_parallelism = 2
   ```

3. Initialize an S3-compatible repository.

   ```sh
   nando --repository "$HOME/nando-data" init \
     --delivery-mode remote \
     --remote-backend s3 \
     --remote-uri s3://my-bucket/nando/
   ```

The endpoint and region belong to runtime TOML; the backend and URI belong to the repository settings. Prefixes are concatenated literally to the object key. For example, `s3://bucket/nando` maps to `nandoobjects/{content_id}`, while `s3://bucket/nando/` maps to `nando/objects/{content_id}`.
