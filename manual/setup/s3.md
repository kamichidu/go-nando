# S3-compatible storage

Amazon S3 and compatible services such as Wasabi use the same `s3` backend.
Choose the backend and bucket URI when initializing the repository; the daemon
uses the endpoint, region, and credentials available at runtime. The endpoint
and region belong under `[remote.s3]`. Credentials are resolved by the AWS SDK
for Go v2 default credential chain; Nando does not have separate S3 credential
settings. See the AWS documentation for
[credential providers](https://docs.aws.amazon.com/sdkref/latest/guide/standardized-credentials.html)
and [shared config profiles](https://docs.aws.amazon.com/sdkref/latest/guide/feature-profiles.html).

The daemon process's operating-system user and environment determine which
shared AWS files, environment variables, and workload credentials it can use.
For a systemd service, credentials must be visible to the service account and
process. A login shell's exported variables are not automatically inherited by
system services; use a supported systemd environment configuration or
credential file with appropriate ownership and permissions. See the
[systemd setup guide](./systemd).

## Amazon S3

For Amazon S3, normally omit `endpoint`; the SDK uses the Amazon S3 endpoint.
Set the bucket's AWS region in `[remote.s3]`:

```sh
mkdir -p "$HOME/.config/nando"
cat > "$HOME/.config/nando/s3.toml" <<'EOF'
[remote.s3]
region = "us-west-2"

[remote]
sync_idle_interval = "30s"
sync_periodic_interval = "5m"
max_delivery_delay = "30m"
sync_parallelism = 2
EOF

nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" init \
  --delivery-mode remote \
  --remote-backend s3 \
  --remote-uri s3://my-bucket/nando/
```

Replace the region and bucket with your values. The examples below illustrate
two standard AWS SDK credential sources. Configure credentials for the same
user and environment that will run `nando daemon`.

To use a named profile, create or configure it with the AWS CLI, then select it
when starting the daemon:

```sh
AWS_PROFILE=archive nando --config "$HOME/.config/nando/s3.toml" \
  --repository "$HOME/nando-data" daemon
```

Alternatively, static access keys can be supplied as standard environment
variables. Put the actual values in your secret manager or service environment;
these placeholders are not credentials. Avoid committing real keys or placing
them in TOML files:

```sh
export AWS_ACCESS_KEY_ID='<your-access-key-id>'
export AWS_SECRET_ACCESS_KEY='<your-secret-access-key>'
nando --config "$HOME/.config/nando/s3.toml" \
  --repository "$HOME/nando-data" daemon
```

On AWS, a workload role can provide credentials through the SDK chain without
static keys. The SDK also supports other standard credential sources; consult
the linked AWS documentation for the full precedence and profile behavior.

## S3-compatible services

For a compatible service, set both `endpoint` and `region` to the values for
your bucket. For example, Wasabi US West 1 (Oregon) uses:

```toml
[remote.s3]
endpoint = "https://s3.us-west-1.wasabisys.com"
region = "us-west-1"

[remote]
sync_idle_interval = "30s"
sync_periodic_interval = "5m"
max_delivery_delay = "30m"
sync_parallelism = 2
```

The endpoint and region vary by service and bucket. Use the same AWS SDK
credential mechanisms described above, supplying the compatible service's
access key and secret through the daemon's environment or an SDK-readable
profile/credentials file.

## Start an adapter

After starting the daemon, use the same config and repository path to start
either adapter:

```sh
mkdir -p "$HOME/nando-mount"
nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" \
  fuse --fuse-mountpoint "$HOME/nando-mount"
```

Or use WebDAV:

```sh
nando --config "$HOME/.config/nando/s3.toml" --repository "$HOME/nando-data" webdav
```

The repository stores the selected backend and URI; the daemon reads the
runtime endpoint, region, credentials, and scheduler settings. The URI prefix
is concatenated literally to object keys, so a trailing `/` is not added
automatically. For example, `s3://bucket/nando` maps to
`nandoobjects/{content_id}`, while `s3://bucket/nando/` maps to
`nando/objects/{content_id}`. The endpoint must support the conditional
single-part upload and checksum behavior Nando requires. See
[Remote delivery](../use/remote-delivery), [FUSE](../use/fuse), and
[WebDAV](../use/webdav) for related behavior.
