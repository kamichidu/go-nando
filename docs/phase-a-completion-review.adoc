The repository has a substantial, tested single-host Phase A implementation: Local and Remote repository modes, the SQLite Metadata and transfer queue, daemon-owned Resource sessions and Recovery, peer CLI/FUSE/WebDAV processes, and real host FUSE and HTTP checks are present. This review does not find a broad failure of the Repository or CAS core.

Phase A is substantially complete under the user's completion judgment. The applicable Phase A invariants are implemented and exercised by source tests and recorded G0–G5 host/emulator evidence; the approved single-user local-host boundary is recorded in the IR. The remaining items below are operational decisions, evidence limits, or explicitly out-of-scope compatibility work, not missing Phase A core invariants:

. Design IR `OPEN-GCS-SCHEDULER-DEFAULTS` still leaves timing defaults and idle semantics unresolved. Remote mode requires all four scheduler settings explicitly; current code measures idle from the last successful content commit observed by the daemon. Scheduling is implemented and exercised without choosing defaults. Local-mode GC scheduling also starts only when these settings are explicitly configured. Keep this as an open, non-blocking deployment-policy decision.

=== WebDAV adapter and protocol-suite scope

Phase A's IR requires a separate WebDAV peer process using the public daemon/Resource contract. The current approved method surface supports dead properties, file and collection COPY, COPY overwrite, and MOVE overwrite, while class 2 locks remain unsupported. Multi-step replacement is not globally atomic; internal detached buffers contain removed or unpublished trees until resumable reclamation completes.

* `LOCK`/`UNLOCK` remain unsupported; `PROPPATCH` and dead properties are implemented. Collection COPY and COPY/MOVE overwrite are supported with bounded per-metadata-operation atomicity and recoverable multi-step partial states. `DAV:1` is advertised; the adapter refuses LOCK/UNLOCK with 501 and omits the unsupported `DAV:supportedlock` capability from allprop/propname; an explicit request returns a 404 propstat. Full Litmus `copymove`, `props`, and `locks` compliance cannot be claimed.
* `nando-webdav` is a separate module/process using controlrpc and daemon file resources. PUT commits before 201/204 and uses Begin-time Entry/revision/absence as its CAS snapshot for conditional PUT. GET/HEAD/PROPFIND and tested namespace methods use daemon state. G5 curl covered the tested operations.
* The approved Phase A boundary is loopback-only unauthenticated HTTP and same-user local operation. WebDAV PUT enforces `If-Match`/`If-None-Match` against the Begin-time CAS snapshot and rejects unsupported conditions. External exposure, client auth, TLS termination, multi-user authorization, and TCP operations are deferred; these are not Phase A acceptance requirements.
* PR #14 records Litmus 0.13-4 results with mixed PASS/FAIL/unsupported groups. Full RFC compliance is not a Phase A acceptance item; broader interoperability remains unverified.

PA-04 is resolved: x/net/webdav's default PROPFIND property generator publishes an exclusive write `<DAV:supportedlock>` even when this adapter intercepts LOCK/UNLOCK and returns 501. The adapter now omits that unsupported property from allprop/propname and responds to an explicit property request with a 404 propstat, without a `lockentry`. RFC 4918 allows resources not to support locking; §6.7 requires `supportedlock` when a resource does support LOCK, and §9.1 requires a 404 result for an explicitly requested property that does not exist. G5 asserts allprop, propname, explicit request, Depth 0/1, `OPTIONS DAV: 1`, and LOCK/UNLOCK 501.

Other unverified WebDAV behavior includes conditions on methods beyond PUT, concurrent HTTP updates, non-empty collection DELETE behavior, MOVE/COPY precondition handling, persisted content-type presentation, and errors at every Resource cleanup boundary. The approved contract covers PUT's Begin-time ETag conditions; this review does not extend that contract to other methods.

[cols="1,2,1"]
|===
|Question |Design-rooted ruling |Completion effect

|Litmus compatibility results
|Full Litmus compliance is not an IR requirement. PR #14 records group outcomes; unsupported operations and failures remain visible and are not counted as Phase A contract failures absent a corresponding IR MUST.
|Non-blocker; no full interoperability claim

|LOCK/UNLOCK
|No lock contract, durability, scope, or Repository interaction is defined. Do not invent one. Returning 501 is an honest unsupported boundary; `supportedlock` is omitted except for explicit requests, which return 404.
|Intentional partial surface; PA-04 resolved

|PROPPATCH/dead properties
|Properties are persisted by Entry ID; PROPPATCH batch is atomic. COPY cloning/overwrite propagation is a later bounded step and can leave committed content with incomplete property propagation.
|Implemented with observable partial-success behavior; not globally atomic with COPY content

|COPY/MOVE constraints
|The approved IR supports recursive collection COPY and COPY/MOVE overwrite. It defines per-metadata-operation atomicity and resumable internal buffers, not global rollback for multi-step replacement. Litmus evidence in this report predates the later implementation.
|Implemented with bounded partial-success semantics; full RFC compliance remains unverified

|WebDAV auth/TLS
|The approved Phase A boundary excludes external exposure, WebDAV client authentication, TLS termination, and multi-user authorization. `OPEN-ADAPTER-AUTHORIZATION` tracks future expansion only. TCP TLS+bearer remains available but its operating lifecycle is not standard Phase A acceptance.
|PA-02 resolved for Phase A; future expansion deferred

|NFS export
|No NFS requirement, component, or acceptance scenario exists; Phase A names FUSE and WebDAV adapters.
|Out of scope; no action

|`nando sync`
|The IR explicitly defers user-directed inter-repository synchronization to Phase 7. This CLI stub is not the Phase A GCS content-ID scheduler.
|Intentionally deferred; no action for Phase A
|===

== Non-blocking follow-ups

. Resolve `OPEN-GCS-SCHEDULER-DEFAULTS` when selecting an operational deployment profile; keep requiring explicit configuration until policy is decided.
. Choose the production GCS evidence threshold (PA-07) before claiming production readiness.
. Keep supported user-service lifecycle evidence current; system-scope runtime remains experimental and outside Phase A acceptance.
. Preserve Litmus per-group outcomes and investigate failures only within the intended WebDAV subset; full RFC compatibility remains unclaimed.
