== Design Principles

The following principles apply across the repository:

. Correctness before optimization.
. The content-addressable object is immutable after commit.
. Metadata becomes visible only after the referenced object is durable and verified.
. Storage backends may differ in implementation, but must expose equivalent observable semantics (SQLite and Firestore share the same semantics).
. Failures must leave either recoverable intermediate state or a previously valid state.
. Repository format and runtime configuration are distinct concerns.
. Design documents describe invariants and ownership; source code describes mechanisms.

== Open Questions

* **Canonical Path Cache Update Strategy** ::
How should the derived Canonical Path Cache (managed by the Metadata Store) be updated when Entry moves or renames occur?
  - *Synchronous Update* (同期更新) -- Recursively update path cache rows atomically during the move/rename transaction.
  - *Invalidate* (無効化) -- Soft-invalidate/clear the affected subtree paths and re-calculate them only when next queried.
  - *Lazy Rebuild* (遅延再構築) -- Queue a background task to rebuild the path cache asynchronously.
