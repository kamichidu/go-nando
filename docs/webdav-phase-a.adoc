= WebDAV Phase A

The adapter in `adapters/webdav/` is a separate Go module and executable process, parallel to `adapters/fuse/`. It depends on the public `controlrpc` contract only. File bytes move through daemon-issued local `file://` Resources; all namespace mutations and commits remain daemon-owned.

== Runtime boundary

The executable defaults to `127.0.0.1:8080` and rejects addresses that resolve outside loopback. It serves plain HTTP without client authentication. This is the approved Phase A boundary: a single local OS user, no external publication, no WebDAV client authentication, and no TLS termination. Those capabilities are deferred for future phases. The standard daemon listener is the per-user Unix socket with a private parent directory (mode 0700) and socket mode 0600. The existing TCP daemon transport remains available only with TLS and bearer authentication; operating its bind, certificate, and token lifecycle is outside standard Phase A.

`PUT` obtains a Begin write session, evaluates `If-Match`, `If-None-Match`, and `If-Unmodified-Since` against the Begin-time expectation, writes and syncs the staging Resource, and returns success only after daemon Commit succeeds. A conditional mismatch aborts the uncommitted session. A Commit conflict is returned as HTTP 412 and is never retried against a newer Entry revision. ETags are strong validators composed from stable Entry ID and committed revision. Unsupported PUT conditional headers, including WebDAV `If`, `If-Modified-Since`, and `If-Range`, receive HTTP 501 rather than being silently ignored. GET/HEAD and PROPFIND use daemon Entry metadata and read Resource sessions; active reads are released when the HTTP file closes.

For stable-Entry FUSE writes, daemon Commit discards staging only when repository metadata authoritatively reports that the Entry is no longer public (`ErrEntryNotFound`). Revision/CAS conflicts and ambiguous or transient failures remain recoverable. The classification comes from the repository visibility/CAS result; clients do not turn a conflict into deletion based on a later lookup. Fsync and final close apply the same result. Remote-mode metadata Commit atomically requires the stable Entry to exist, so GC cannot remove its detached row between classification and commit and allow the same ID to be recreated. Internal-buffer COPY leases are separate from Resource-session and Resource-lock leases. An expired COPY lease is atomically claimed and fenced; a GC claim is durable under the single-daemon repository process lock, has no runtime renewal/expiry, and is reset and re-fenced only during restart recovery after acquiring that lock.

== Phase A method surface

[cols="1,2"]
|===
|Method |Behavior

|GET, HEAD
|Read file bytes; x/net/webdav handles HTTP range and date validators.

|OPTIONS
|Advertises DAV class 1 and the supported method list.

|PROPFIND
|Lists the repository hierarchy and live properties using x/net/webdav XML support. `DAV:supportedlock` is omitted from allprop/propname because Phase A does not support locks; an explicit request for it is returned in a 404 propstat, without a lockentry.

|PUT
|Full-file replacement/create with Commit-before-success and HTTP entity-tag/date preconditions.

|DELETE, MKCOL
|Daemon-owned namespace remove/create operations.

|MOVE
|Daemon-owned path move; `Overwrite: F` rejects an occupied destination with 412. Replacement is supported through per-operation metadata moves and best-effort displaced-tree reclamation.

|COPY
|File and collection copy with `Overwrite: T` by default or `F` explicitly. Collection COPY accepts `Depth: 0` and `Depth: infinity` (default). Existing destinations return 204; creation returns 201. Collection construction and replacement use multiple bounded metadata operations and can leave recoverable partial state on failure.

|LOCK, UNLOCK
|501 Not Implemented. The design does not select lock persistence, scope, or interaction with repository CAS.

|PROPPATCH / dead properties
|Atomic batch PROPPATCH stores opaque XML keyed by Entry ID and expanded property name. PROPFIND returns dead properties and basic live properties. Protected live properties return 403 and dependent properties 424. MOVE retains properties, COPY clones them, DELETE removes them, and PUT preserves them.

|COPY/MOVE failure boundary
|Collection COPY, COPY overwrite, and MOVE overwrite are supported. Each metadata transaction and individual namespace Move is atomic. Multi-step replacement, dead-property propagation, and displaced-tree reclamation are not globally atomic. Errors report committed changes or recovery paths; detached cleanup roots are hidden internal buffers reclaimed resumably.
|===

For file COPY, any failure after BeginWrite attempts daemon `Abort`; it never treats Release alone as successful cleanup. A Commit CAS failure leaves the prior file content authoritative. Collection COPY builds a detached internal tree before publishing its root. Existing collection replacement and MOVE replacement use atomic individual namespace moves, then cleanup. Failures between those steps may leave a backup name or internal buffer; the response identifies partial completion and the recovery path. No multi-entry transactionality or crash-atomic subtree replacement is claimed.

== Internal detached metadata buffers

SQLite maintains a dynamically sized registry of independent private buffers. Each buffer identifies one detached subtree root whose `parent_id` is unset. Ordinary path traversal, Entry-ID lookup, property access, and listings cannot expose that root or its descendants. Object-reference enumeration continues to count buffered files until reclamation deletes their metadata, so object GC cannot remove content while cleanup is pending.

Collection COPY uses a separate internal-buffer lease with a 30-second TTL and a 5-second renewal interval. Lease renewal and every staging mutation, publication, and expiry claim compare the fencing token in the same SQLite transaction. An expiry claim increments the token and blocks stale COPY owners from changing or publishing the tree. At daemon restart, after acquiring the repository process lock, the daemon fences leases from the previous process and resumes cleanup; failed COPY cleanup expires its own lease and enters the same reclamation path. This lease is intentionally separate from Resource-session and Resource-lock leases.

Recursive `DELETE` linearizes when one SQLite transaction verifies the selected root's observed parent and revision, removes it from the public namespace, and registers its buffer. A concurrent `MOVE` that commits first changes the observed revision or parent and makes the stale detach fail. After detach, public moves cannot take descendants out of the buffer. Cleanup walks bottom-up and deletes one Entry per transaction. A failure or daemon crash leaves the buffer registered; the daemon retries immediately on startup and periodically while running. Buffer cleanup is independent of object GC and does not block unrelated namespace operations.

FUSE read handles keep their already-open immutable Resource and renewable content RLock until Release. Open write handles retain their daemon staging session and file descriptor; FUSE unlink records durable discard intent before namespace removal, and detached writes cannot Commit. If another adapter detaches a parent subtree, handle Getattr and Setattr continue from the held Resource and cached inode state; stable-ID write Commit becomes discard-only and does not create an ordinary Recovery record. Collection COPY uses a private buffer for construction and publishes the copied root in one metadata operation. MOVE and COPY replacement may still expose recoverable intermediate namespace state because the complete protocol operation spans multiple transactions.

The adapter evaluates WebDAV entity-tag conditions against the same Begin-time CAS snapshot used by Commit, avoiding a Stat/Begin race. A concurrent update after Begin therefore fails repository CAS rather than overwriting newer content. Entry conflicts map to HTTP 412; absent resources map to 404; namespace collisions map to 412 or 405 according to the operation surface. `OPTIONS` advertises `DAV: 1`; it does not advertise class 2 locking, consistent with LOCK/UNLOCK returning 501.

link:https://www.rfc-editor.org/rfc/rfc4918.html#section-6.3[Section 6.3] makes locking optional, and link:https://www.rfc-editor.org/rfc/rfc4918.html#section-6.7[Section 6.7] requires `DAV:supportedlock` for resources that do support LOCK. This adapter supports no lock types, so it does not publish that property as if an exclusive write lock existed. link:https://www.rfc-editor.org/rfc/rfc4918.html#section-9.1[Section 9.1] requires a 404 result when an explicitly requested property does not exist; explicit retrieval is therefore reported as a missing property (404 propstat), not as an empty lock capability declaration.

== Validation

`e2e/run.sh` adds host-native G5 curl coverage for OPTIONS, GET/HEAD, PUT, ETags and conditional PUT, MKCOL/PROPFIND, atomic PROPPATCH, dead-property lifecycle across MOVE/COPY/DELETE/PUT, MOVE, file COPY, DELETE, and explicit unsupported lock responses. G0 includes tests, race, lint, and build for the independent module. G7 Litmus results remain separate; full WebDAV compliance remains unverified because locking is not implemented and multi-step replacement has limited atomicity.
