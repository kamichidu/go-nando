= State Machines

This document describes the state transitions and lifecycle rules for logical Entries, physical Objects, and Lease coordination keys.

== Entry State Machine

An Entry represents a logical file or directory in the metadata database. Its lifecycle is governed by the following state machine:

[source,text]
----
Create -> Ready -> Rename -> Move -> Delete
----

=== Lifecycle States and Transitions

1. **Create** ::
The entry metadata is written to the store (either as `pending` or initialized state).
* *Revision*: Initialized to `1`.

2. **Ready** ::
The entry is successfully committed and made visible to logical read queries.
* *Revision*: Remains `1` if initialized at creation, or increases by `1` if transitioned from a pending state during commit.

3. **Rename** ::
The entry's base `Name` attribute is changed within its current directory.
* *Revision*: Increments by `1` on successful commit.

4. **Move** ::
The entry's parent relationship (`ParentID`) is changed to move it to a different directory.
* *Revision*: Increments by `1` on successful commit.

5. **Delete** ::
The entry is soft-deleted, moving its state to `deleted`, and removing it from active namespaces and referenced hash queries.
* *Revision*: Increments by `1` on successful commit.

=== Revision Increment Rule Summary

* The `Revision` increments by `1` **only at the successful commit** of any write transaction modifying the entry (such as transition to `ready`, `rename`, `move`, or `delete`).
* Child mutations (renaming, moving, or deleting children) do **not** increment the parent directory's revision.

== Object State Machine

A physical object's lifecycle in the Content Addressable Storage follows these steps:

[source,text]
----
Acquire Lease -> Upload -> Commit -> Release Lease
----

=== States

1. **Acquire Lease** ::
A lease on the object's hash is acquired to claim the upload task.

2. **Upload** ::
The raw bytes of the object are transmitted to the Object Store (staging, temp, or direct cached backend upload).

3. **Commit** ::
The object is atomically published to the durable objects storage layer and verified.

4. **Release Lease** ::
The lease is deleted, indicating completion of the upload/commit workflow.

== Lease State Machine

Leases are temporal keys used to prevent redundant, concurrent uploading tasks. A Lease's state machine is:

[source,text]
----
Acquire -> Active -> Released
           or
Acquire -> Active -> Expired
----

=== Transitions

* **Acquire** ::
A client requests a Lease on a specific cryptographic hash. If no active, unexpired lease exists on that hash, the lease is granted.

* **Active** ::
The lease is actively held, protecting the upload process. The expiration time is set: `ExpiresAt = now + TTL`.

* **Released** ::
Upon a successful Object Commit, the client explicitly deletes/releases the Lease, freeing it immediately.

* **Expired** ::
If the upload process is interrupted or fails to commit within the lease window, the lease expires silently once `now >= ExpiresAt`. Other clients can now acquire a new lease on the hash.
